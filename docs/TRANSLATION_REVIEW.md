## 구현에서 확인한 관련 요인

1. **의미 검사 부재:** 현재 출력 검사는 JSON 구조와 한국어 문자 여부를 확인한다. 한국어 교정 결과도 주로 길이 제한으로 걸러내므로 부정·조건·행위가 바뀐 문장이 통과할 수 있다.
2. **교정과 정확성 확인의 차이:** 한국어 표현 교정 프롬프트에 원문은 있지만, 부정과 조건 관계를 구조적으로 비교하는 별도 검사는 없다. 같은 모델이 초안과 교정을 수행하므로 교정 횟수만으로 정확성을 보장할 수 없다.
3. **짧은 문장의 문맥 제외:** `hasContextWorthyText`는 공백·문장부호를 제외한 원문이 8자를 초과해야 주변 대사를 전달한다. 이름을 부르는 말이나 짧은 반응, 다른 말풍선에 이어지는 문장은 문맥을 받지 못할 수 있다.
4. **설명문과 대사가 같은 문맥 목록에 들어감:** 페이지의 블록들을 같은 읽기 순서로 묶는다. 잘못 인식된 오른쪽 인물 소개가 주변 대사의 문맥으로 섞일 수 있다. 이 표본에서 오류를 실제로 유발했는지는 확정하지 않았지만 구조상 가능한 경로다.
5. **인명 읽기 정보 부족:** OCR 원문에는 이름의 후리가나가 별도로 보존되지 않고, 현재 작품 용어집은 비어 있다. 번역기가 한자 이름의 읽기를 추측하게 된다.
6. **OCR 오류의 번역 확정:** 오른쪽 설명 영역의 OCR 결과는 실제 이미지에 없는 내용인데도 매끄러운 한국어로 번역·저장됐다. 형식상 정상인 문장에 대한 OCR 이상 탐지와 검토 표시가 필요하다.

## 개선 우선순위

1. 위 표본의 OCR 오류·인명·누락을 고친 검토용 기준 문장을 확보한다.
2. 부정, 조건, 대조, 행위자, 인명 보존을 우선하는 의미 검토를 추가한다. 추가 추론 비용을 고려해 의심 문장부터 검토한다.
3. 짧은 대사에도 문맥을 제공하고, 인물 소개·효과음·본문 대사를 문맥 그룹에서 구분한다.
4. 작품별 인명 읽기와 표기를 용어집에 등록하고, 임의의 한글 이름으로 바뀌지 않았는지 검증한다.
5. 긴 세로 설명문을 적절한 읽기 단위로 나누어 OCR하고, 불확실한 결과는 검토 필요 상태로 표시한다.

이 검토에서는 코드나 실제 아카이브 데이터를 수정하지 않았으며, 모델을 추가로 실행하지 않았다.
