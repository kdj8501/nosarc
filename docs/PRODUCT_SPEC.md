# Nos Arc 제품 요구사항

## 1. 목표 사용자와 사용 시나리오

주 사용자는 자신의 서버에 보관한 일본 만화를 혼자 읽는 관리자다. 사용자는 사이트에 접속해 공유 비밀번호를 입력하고, 작품을 선택하거나 새 작품과 화를 업로드한다. 번역을 선택한 업로드는 백그라운드에서 처리되고, 사용자는 작업이 끝날 때까지 다른 작품을 읽을 수 있다.

## 2. 인증 요구사항

### 비밀번호 화면

- 프로젝트명은 `Nos Arc`로 관리하고 브라우저 제목에 사용한다.
- 본문에는 `assets/uma.gif`와 비밀번호 입력창만 둔다.
- 비밀번호 입력 후 Enter로 제출한다.
- 성공하면 HttpOnly 세션 쿠키를 발급하고 서재로 이동한다.
- 실패 시 입력창의 시각 상태와 접근 가능한 오류 상태만 갱신한다. 별도 로그인 ID, 회원가입, 비밀번호 재설정 화면은 만들지 않는다.
- 비밀번호 원문은 코드, 데이터베이스, 로그에 기록하지 않는다.
- 짧은 시간에 반복 실패하면 IP와 세션 기준으로 지연 또는 잠금을 적용한다.

### 환경 변수 계약

개발 환경에서는 다음처럼 설정할 수 있다.

```dotenv
NOSARC_ACCESS_PASSWORD=change-this-password
SESSION_SECRET=replace-with-a-long-random-value
```

운영 환경에서는 `NOSARC_ACCESS_PASSWORD_HASH`에 Argon2id 해시를 넣고 원문 변수는 비워 둔다. `.env`는 Git에 커밋하지 않으며 `.env.example`만 예시 값으로 제공한다.

## 3. 작품과 카테고리

### 작품

작품은 만화 이름을 기준으로 하나의 카테고리로 관리한다. 기본 필드는 다음과 같다.

| 필드 | 설명 |
|---|---|
| 이름 | 필수, 화면에 표시할 만화 제목 |
| 원제 | 선택, 검색과 번역 프롬프트에 사용할 원문 제목 |
| 설명 | 선택 |
| 표지 | 선택, 업로드된 첫 페이지와 별도 지정 가능 |
| 장르 태그 | 0개 이상, 미리 정의된 태그 또는 새 태그 |
| 번역 언어 | 기본 `ko`, 작품별 변경 가능 |
| 공개 상태 | 아카이브 내부에서만 `active`, `archived` |

장르 태그와 작품은 다대다 관계로 둔다. 예시는 `액션`, `로맨스`, `판타지`, `코미디`, `드라마`, `스릴러`, `일상`, `성인`이며 사용자가 추가할 수 있다. 태그는 분류용 메타데이터일 뿐 파일 경로에 포함하지 않는다.

### 화

각 작품에 여러 화를 연결한다.

- 화 번호는 필수이며 정수 또는 `0.5`, `외전` 같은 표시 문자열을 함께 지원할 수 있다.
- 같은 작품 안에서 표시 순서를 명시적으로 저장한다.
- 화 제목, 업로드 날짜, 원본 파일, 페이지 수, 번역 상태를 표시한다.
- 같은 화 번호가 이미 있으면 덮어쓰지 않고 사용자에게 교체 여부를 확인한다.
- 원본과 파생 산출물은 화 단위 디렉터리와 데이터베이스 ID로 연결한다.

## 4. 업로드 요구사항

### 지원 입력

MVP에서 지원할 입력은 다음과 같다.

| 종류 | 확장자 | 처리 방식 |
|---|---|---|
| 이미지 | JPG, JPEG, PNG, WEBP, GIF, TIFF | 한 파일을 한 페이지로 처리 |
| 문서 | PDF | 페이지별 이미지로 변환 |
| 만화 묶음 | CBZ, ZIP | 안전하게 압축 해제 후 이미지 정렬 |
| RAR 묶음 | CBR, RAR | RAR 도구가 설치된 경우 지원, 아니면 명확한 오류 반환 |
| 선택 지원 | AVIF, HEIC | 런타임 코덱이 설치된 경우에만 활성화 |

“모든 포맷”은 확장자를 무제한 허용한다는 뜻으로 구현하지 않는다. 이미지로 변환할 수 있는 포맷은 플러그인 방식으로 확장하고, 지원하지 않는 포맷은 업로드 전에 차단한다. 확장자와 MIME을 함께 확인하고 실제 파일 시그니처도 검사한다.

### 업로드 폼

- 기존 작품 또는 새 작품 선택
- 화 번호 입력
- 화 제목 선택 입력
- 파일 선택 또는 드래그 앤 드롭
- 원본 언어 선택, 기본 `ja`
- 번역 여부 체크박스, 기본 해제 또는 사용자 설정으로 결정
- 번역 언어, 기본 `ko`
- 업로드 후 즉시 작업 ID와 현재 상태 반환

업로드가 성공하면 원본 저장과 작업 등록까지만 요청-응답에서 수행한다. PDF 렌더링, 압축 해제, OCR, 번역, 페이지 인덱싱은 요청 스레드에서 실행하지 않는다.

## 5. 번역 흐름

번역 체크가 꺼져 있으면 파일 정규화와 페이지 인덱싱까지만 수행한다. 켜져 있으면 다음 단계를 순서대로 실행한다.

1. 입력 검증과 안전한 압축 해제
2. PDF·이미지를 표준 페이지 이미지로 정규화
3. 텍스트 영역 감지 및 일본어 OCR
4. 텍스트 정리, 읽기 순서 추정, 이름·용어 사전 적용
5. 일본어에서 한국어로 문장 단위 번역
6. 원문과 번역문, 영역 좌표, 신뢰도 저장
7. 리더에서 사용할 오버레이 생성
8. 화 상태를 `ready`로 변경

MVP는 원본 페이지 위에 번역 오버레이를 얹는 방식으로 시작한다. 원본을 지우고 배경을 복원하는 이미지 인페인팅은 별도 작업이며, 품질과 CPU 시간을 검증한 뒤 추가한다.

## 6. 비동기 작업 상태

작업 상태는 다음과 같이 정의한다.

`queued` → `preparing` → `ocr` → `translating` → `rendering` → `completed`

실패 시 `failed`, 사용자가 취소하면 `cancelled`가 된다.

- 각 단계는 현재 단계, 완료 페이지 수, 전체 페이지 수, 시작·종료 시간, 오류 메시지를 저장한다.
- 실패한 단계부터 재시도할 수 있어야 한다.
- 같은 원본 해시와 같은 모델 버전으로 이미 성공한 결과는 재사용한다.
- 작업 목록은 리더 화면과 분리된 전역 패널에서 확인한다.
- 브라우저를 닫아도 작업은 계속된다.

## 7. 리더 요구사항

- 일본 만화의 세로 읽기 방향을 기본으로 지원한다.
- 페이지 이동, 첫 페이지·마지막 페이지, 키보드 방향키를 지원한다.
- 원본 보기와 번역 오버레이 보기를 즉시 전환한다.
- OCR 원문, 번역문, 신뢰도가 낮은 영역을 관리자에게 표시한다.
- 번역 결과가 아직 없으면 원본은 바로 읽을 수 있고, 작업 완료 후 새로고침 없이 상태를 갱신할 수 있다.
- 번역문을 직접 수정하고 작품별 용어 사전에 저장할 수 있는 편집 기능은 2단계에서 추가한다.

## 8. 완료 기준

- 비밀번호를 모르면 어떤 작품·파일 API에도 접근할 수 없다.
- 올바른 비밀번호 입력 후 서재, 작품, 화, 리더가 접근된다.
- JPG 한 장, 여러 이미지 묶음, PDF, CBZ를 각각 화로 등록할 수 있다.
- 업로드 응답은 작업 완료를 기다리지 않고 반환된다.
- 번역을 선택한 작업은 브라우저를 닫아도 계속되고 재접속 후 상태가 보인다.
- OCR·번역 오류가 발생하면 원본은 보존되고 해당 작업만 재시도할 수 있다.
- 동일한 원본을 다시 업로드해도 캐시 정책에 따라 중복 처리를 피하거나 사용자에게 명확한 선택지를 준다.
